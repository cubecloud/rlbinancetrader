# PLAN — ветка feature/strategy_v6_to_rl

Цель: RL-надстройка над доказанной деньгами механической стратегией v6
(RegimeDipBuyerC2B3 из проекта sunday) с узкой свободой — тайминг выходов.
НЕ end-to-end агент с нуля. Якорь — behavioral cloning (BC) копии v6,
награда — настоящий P&L симулятора, валидация — walk-forward с пермутацией
и мультисидом.

Статус документа: черновик v0.1 (2026-07-22). Обсуждается поэтапно;
каждый этап согласовывается с пользователем до начала работ по нему.

---

## Архитектурные принципы (согласованы 2026-07-22)

- П1. Источник истины — база (PG): OHLCV + поминутные предсказания голов
  (buy/sell). Кэш (материализация окон в память/на диск) — только ускоритель.
  Манифест кэша: границы окна, версия билдера признаков, хэш.
- П2. Параметры стратегии (thresholds, SL, TP, cooldown, ...) — атрибут
  стратегии, не данные. Эталон — замороженный JSON пакета v6 (sha256).
- П3. Сигнальный тракт (q_buy/q_sell, пороги, режим, нога зигзага, bounce)
  не переписываем: подключаем код sunday (state-билдер, зеркальная логика)
  как библиотеку. Вторая реализация = вечный риск расхождения.
- П4. Observations проектируются отдельно под агента (стратегии они не
  нужны): рынок + внутренности тракта + контекст текущей сделки.
- П5. Multiprocessing и скорость закладываются с этапа 0 (векторные среды);
  выбор ML-стека — по бенчмарку, не по вере.
- П6. Референс-зеркало sunday не ускоряем и не модифицируем — это эталон
  парности для отбора кандидатов.
- П7. Один код тракта на всех этапах (train → отбор → paper → live),
  train/serve skew закрыт по построению.
- П8. Дисциплина экспериментов: pre-reg критериев ДО прогона, одно изменение
  за раз, walk-forward (никаких shuffle), пермутационный контроль, мультисид
  (сид-разброс у sunday бывал больше эффекта), гейт — только компаунд/MaxDD
  против якоря «делай как v6». AP/accuracy/val_pr_auc ≠ деньги.
- П9. Реиспользуем инфраструктуру rlbinancetrader: BinanceEnvCash (механика
  step по предвычисленным признакам), spaces/маски, rewards, LabSubprocVecEnv,
  rllab.LabBase (эксперименты, чекпойнты, tensorboard), экстракторы customnn.
  Не тащим: orderbook.py, онлайн-слой старого дизайна, MpCacheManager-сокеты.

## Этап 0 — Фундамент: данные, стратегия-модуль, стек

- 0.1 Окружение: conda-env для ветки (py3.10; SB3 2.3.2 как база).
      Проверить совместимость pandas<2 / gymnasium 0.29.1 с кандидатами
      стека (SBX/JAX); при необходимости — отдельный env посвежее.
- 0.2 Data-слой: доступ к PG (OHLCV spot BTCUSDT 1m + предсказания голов
      v6), интерфейс «окно → (ohlcv_df, features_df)». Кэш-материализация
      окна с манифестом (П1). Проверка: NaT-guard на живом крае
      (паттерн из sunday).
- 0.3 Strategy-модуль: механика v6 как импортируемая библиотека
      (state-билдер сигнального тракта + пошаговая логика входов/выходов
      с параметрами из frozen JSON).
      Гейт 0.3: parity-тест — сделки и P&L совпадают с эталонными фолдами
      зеркала sunday (допуск: известное смещение warmup ноги зигзага).
- 0.4 Бенчмарк стеков на мини-среде (реальные данные, укороченное окно):
      SB3 vs SBX vs PufferLib. Метрики: env шаги/сек (1 процесс и вектор),
      время «эпохи» обучения PPO, совместимость с маскированием.
      Решение по стеку фиксируется в этом файле.

## Этап 1 — Среда (gym) поверх data-слоя и strategy-модуля

- 1.1 Каркас среды: режимы snapshot (обучение, воспроизводимо) и online
      (paper/live поверх свежих строк PG). База — BinanceEnvCash с заменой
      источника данных (П9).
- 1.2 Action space (РЕШИТЬ ДО РЕАЛИЗАЦИИ, открытый вопрос №1):
      А) в позиции каждую минуту: {держать, выйти};
      Б) сдвиг штатного выхода v6 в окне ±N минут.
      SL/circuit-breaker у агента не отбираются: выйти раньше стопа можно,
      позже — нельзя.
- 1.3 Observation-дизайн (отдельное обсуждение, подэтапы):
      1.3.1 группы признаков: рынок (производные), тракт (уверенности голов,
            отступ от порога, режим, нога), контекст сделки (нереализованный
            P&L, длительность, откат от пика сделки, расстояние до SL/TP) —
            последнюю группу среда вычисляет сама;
      1.3.2 нормализация/скейлинг (без утечки: параметры скейла — только из
            train-окна);
      1.3.3 lookback: нужен ли, глубина, формат (вектор vs 2D под
            Hybrid/LSTM экстракторы).
- 1.4 Reward: P&L закрытой сделки из strategy-модуля (компаунд-семантика),
      без суррогатов и без геометрических меток разворотов.
      Гейт 1.4 (smoke): политика «повторяй v6» в нашей среде воспроизводит
      сделки и P&L strategy-модуля бит-в-бит.
- 1.5 Векторизация: LabSubprocVecEnv/выбранный стек, прогрев кэша,
      замер пропускной способности на полном окне.

## Этап 2 — BC-клон v6 (якорь)

- 2.1 Экспертный датасет: траектории v6 (observation, действие) по всей
      истории; разметка — из strategy-модуля.
- 2.2 Обучение BC-головы (стартово — MlpExtractor/Hybrid из customnn).
      Гейт 2.2 (pre-reg, порог согласовать): клон повторяет решения v6
      с точностью, при которой P&L прогона клона в среде статистически
      неотличим от v6 (допуск по сделкам и по компаунду — зафиксировать
      числом ДО обучения).
- 2.3 Мультисид BC (5 сидов): разброс метрик повторения — в допуске.

## Этап 3 — RL-надстройка (только выходы)

- 3.1 Pre-reg документ: критерии успеха/провала, окна, сиды, контроли —
      ДО первого прогона. Шаблон — pre-reg манифесты sunday.
- 3.2 RL fine-tune от BC-весов: свобода только на выходе (П2, п.1.2),
      KL-штраф за отклонение от якоря; коэффициент KL — часть pre-reg.
- 3.3 Контроли: пермутация наград (на случайных наградах улучшение = 0),
      мультисид 5, сравнение с якорем на каждом фолде.
- 3.4 Walk-forward (открытый вопрос №2 — геометрия разбиения):
      базовый вариант: train 2021-01..2024-03 / валидация 2024-03..2026-07;
      альтернатива: скользящие фолды внутри 2024+. Эпохи рынка статистически
      разные — смешивание вслепую запрещено (урок sunday).

## Этап 4 — Отбор и путь в прод

- 4.1 Кандидаты (пережившие 3.3/3.4) прогоняются через референс-зеркало

- 4.2 Финальный гейт: компаунд/MaxDD против якоря v6; критерий — из

- 4.3 Деплой-контур (проработать к концу этапа 3): варианты

- 4.4 Paper-стадия с собственным pre-reg вердиктом (по образцу v6:

## Правила работы (выжимка договорённостей)

- Никаких подписей/атрибуции Claude в git (коммиты, push, PR).
- «А можем X?» = обсуждение, не команда запуска. Дорогие прогоны — только
  после явного «запускай»; параметры согласовываются ДО.
- Старый код не ломать: копировать-переименовывать; правки существующих
  файлов — diff и «да» пользователя; чекпоинт-коммит перед правками.
- Длинные прогоны — tmux, логи через FileHandler; после старта трейна —
  доклад первой эпохи; далее статусы.
- Общение: русский, просто, с числовыми примерами; техтермины не переводить.
