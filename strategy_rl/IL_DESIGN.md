# 1.2* — Выбор IL-подхода (сравнение для обсуждения)

Черновик v0.1, 2026-07-23. Решение определяет action space (см. PLAN.md 1.2*).

## Наша специфика (что делает задачу нетипичной)

1. Эксперт — ДЕТЕРМИНИРОВАННАЯ механика (не человек): для ЛЮБОГО состояния
   можно бесплатно спросить «что сделала бы стратегия?». Разметка не
   ограничена посещёнными траекториями — редкий козырь.
2. Экономических событий мало (~140 сделок/эпоху), но минутных состояний
   много (2.9 млн). IL учится на состояниях (дёшево), RL — на исходах
   сделок (дорого и мало).
3. Один исторический путь рынка → любое on-policy исследование склонно
   к заучиванию траектории.
4. Оценка — парная («та же сделка, другой выход»), значит вмешательства
   агента должны быть локальными, не перекраивающими расписание сделок.

## Варианты

### А. Чистый BC (supervised: state → действие эксперта)
Обучение на всех минутах обеих эпох. Простой, быстрый, стабильный.
- Плюс: максимум данных; клон = якорь для всего дальнейшего.
- Минус: ковариатный сдвиг — клон видел только состояния, где ходила
  стратегия; стоит агенту отклониться, он в незнакомой зоне и ошибки
  накапливаются (классическая болезнь BC).
- Роль у нас: НЕОБХОДИМЫЙ этап в любом варианте (гейт 2.2), но
  недостаточный для улучшения.

### Б. BC + DAgger-подобное дообучение
Итерации: катаем ТЕКУЩУЮ политику в среде → собираем посещённые ею
состояния → эксперт размечает их (у нас бесплатно, п.1 специфики) →
доучиваемся на объединённой выборке.
- Плюс: лечит ковариатный сдвиг ровно там, где агент реально ходит;
  использует наш козырь детерминированного эксперта на 100%.
- Минус: учит ПОВТОРЯТЬ эксперта, сам по себе улучшения не даёт —
  нужен этап RL/оптимизации сверху.
- Роль у нас: усилитель якоря — «клон, который не разваливается при
  отклонениях». Дёшев (разметка бесплатна), совместим с любым RL сверху.

### В. Offline RL (CQL / IQL / AWAC) на траекториях эксперта + контрфактах
Учимся сразу на «наградной» задаче по логам, без взаимодействия со средой.
- Плюс: не трогает среду, консервативен по построению.
- Минус: наш датасет наград — ~280 сделок с ОДНОЙ политикой сбора данных;
  offline RL на таком объёме и с таким однообразием policy coverage — это
  экстраполяция в пустоту, конкретно то, от чего CQL/IQL защищаются
  зануляя всё незнакомое → на выходе почти наверняка получим BC с лишними
  сложностями. Библиотеки (d3rlpy) — ещё одна зависимость.
- Роль у нас: НЕ рекомендую как основной путь. Возможен как контроль
  («согласен ли IQL-advantаge с нашим RL» — дёшево проверить позже).

### Г. IL-якорь + on-policy RL fine-tune с KL (исходный план)
BC/DAgger-веса → PPO с наградой из симулятора + KL-штраф к якорю.
- Плюс: единственный вариант, который ИЩЕТ улучшение, а не повтор;
  KL-якорь ограничивает отклонения (управляемая свобода); совместим
  с парной оценкой (свобода узкая).
- Минус: все ловушки on-policy на одном пути рынка (заучивание) —
  закрываются блоком 3.3 (анти-мемоизация, нижний/верхний бенчмарки,
  канарейка утечки).

## Рекомендация (моя, на обсуждение)

Конвейер **А → Б → Г**: BC на всех минутах → DAgger-докатка на состояниях,
посещаемых политикой (бесплатная разметка) → PPO с KL к этому якорю
и наградой из зеркала. Вариант В — не строить, оставить как поздний
дешёвый контроль.

## Следствия для action space (обсудить вместе с выбором)

- Для парной оценки (П10) свобода должна быть ЛОКАЛЬНОЙ. Базовый кандидат:
  в позиции {держать, выйти} с ограничением «не позже штатного выхода+SL»
  (вариант А из PLAN 1.2), НО с полным replay при оценке (сдвиг cooldown →
  пересчёт последующих входов) — среда это уже умеет по построению.
- Новость из sunday (вето ожило на честных метках) открывает вопрос о
  свободе и на ВХОДЕ ({войти, пропустить} на сигнальном баре). Предлагаю:
  НЕ включать в первую итерацию (хвостовой риск, урок №2), но
  спроектировать action space расширяемым (маска действий уже есть в
  инфраструктуре) и вернуться после pre-reg подтверждения вето-сигнала
  sunday.
- SL/circuit-breaker неприкосновенны в любом варианте.

## Открытые вопросы к обсуждению

3. Вход в action space первой итерации — нет (моя рекомендация) или да?
