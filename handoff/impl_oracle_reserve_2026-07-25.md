## 1. Что сделано (механика)

- Ранний выход — через `AgentHookBT.exit_policy` (только oracle видит будущее,
  `v7hook.py:33-45`). Цена выхода строго `open(i+1)*(1-comm)` — как исполняет
  `position.close()` при `trade_on_close=False`. Никакого `max(High)`.
- Oracle = per-сделочный максимум: выйти на баре с максимальным `open` в окне
  `[entry+2 .. exit-1]`, только если это лучше штатного выхода v7 (иначе держим).
  Отсюда **frozen-дельта ≥ 0 по построению**.
- Сверка базы: чистая v7 через харнесс = **162/162 (A)** и **272/272 (B)**
  сделок, `entry_mismatch=0` против судей — база верна.
- Тройной отчёт: (A) frozen парные дельты; (B) полный движок; (C) цена cooldown
  + дельта трейдбука. Цена cooldown замерена подклассом
  `AgentHookNoCooldownBT`, где агентский выход НЕ взводит cooldown.

## 3. Декомпозиция лузеры / винеры

- **Экономия на лузерах-SL (компонента б):** A = 73.54 п.п., B = 314.40 п.п.
  На одну SL-сделку это ~8.2 п.п. (A) и ~8.5 п.п. (B): oracle уводит сделку с
  пути к −7% SL в небольшой плюс на пред-SL пике. Природа разная по объёму:
  в B вдвое-втрое больше SL-сделок (37 против 9), поэтому валовый резерв (б)
  там в 4 с лишним раза выше.
- **Экономия на прочих лузерах** (dip, закрытых signal/legflip в минус):
  основная масса frozen-резерва (A: 219 п.п.; B: 314 п.п.) — это НЕ то, что
  режет жёсткое правило SL; это решения, которые и передаются агенту.
- **Потеря на винерах (TP):** на frozen = 0 по построению (oracle не рубит TP —
  доля сохранённых TP = **1.0** в обеих эпохах). Реальная потеря на винерах
  возможна только через knock-on полного движка (cooldown), см. §5.

## 4a. ХРУПКОСТЬ КОМПОНЕНТЫ (б) — leave-one-out по SL-бакету (РЕШАЮЩЕЕ)

Гейт: `(б)/n_dip < 0.5%` → мертва, т.е. линия смерти в п.п. = `0.5 × n_dip`.

| | A 2024-26 | B 2021-24 |
|---|---|---|
| n_SL (dip) | 9 | 37 |
| (б) сумма | 73.54 п.п. | 314.40 п.п. |
| линия смерти (0.5×n_dip) | 73.00 п.п. | 122.50 п.п. |
| **запас над линией** | **+0.54 п.п.** | **+191.90 п.п.** |
| мертва после удаления k SL-сделок | **k=1** | k=20 |

- **Эпоха A: вердикт НЕ определён данными.** Запас +0.54 п.п. в ~15 раз меньше
  вклада ОДНОЙ SL-сделки (среднее 8.17 п.п.). Удаление любой одной из 9 SL
  уводит (б) под порог → DEAD. При 9 сделках это coin-flip, а не результат.
  Честный заголовок по A: **indeterminate**.
- **Эпоха B: вердикт устойчивый ALIVE.** Запас 2.6× над линией; чтобы уйти под
  порог, надо выбросить 20 из 37 SL-сделок. Резерв реален.

## 5. Полный движок и цена cooldown — ВАЖНОЕ ПРЕДУПРЕЖДЕНИЕ

| | A 2024-26 | B 2021-24 |
|---|---|---|
| Return v7 | 267.46% | 98.11% |
| Return oracle (cooldown как есть) | 3069.04% | 22690.77% |
| Return oracle (cooldown отключён) | 2071.60% | 4298.88% |
| Reserve_B (cd) | +2801.58 п.п. | +22592.66 п.п. |
| цена cooldown (no-cd − cd) | **−997.44 п.п.** | **−18391.89 п.п.** |
| трейдбук v7 → oracle(cd) → (no-cd) | 162→209→233 | 272→370→432 |
| новых cooldown от oracle | 126 | 169 |

**Компаунд движка с предвидением ВЗРЫВАЕТСЯ (3069%, 22690%) и path-chaotic.**
Это НЕ «резерв» — это верхняя-верхняя граница: oracle с идеальным знанием
будущего рекомпаундит капитал на пиках. Числа Reserve_B (компаунд) для вердикта
**НЕ используются** (эпоха A вдобавок anchor-inflated). Гейт живёт в frozen (§2).

### Цена cooldown — правильный замер в СУММА-пространстве (не компаунд)

Компаунд path-chaotic, поэтому цена cooldown замерена дополнительно в СУММЕ
посделочных `return_pct` (без компаунда — те же единицы, что и frozen-резерв):

| | A 2024-26 | B 2021-24 |
|---|---|---|
| Σ return_pct v7 | 143.3 п.п. | 102.3 п.п. |
| Σ return_pct oracle (cd) | 361.2 п.п. | 579.3 п.п. |
| Σ return_pct oracle (no-cd) | 324.4 п.п. | 422.0 п.п. |
| **цена cooldown (no-cd − cd)** | **−36.8 п.п.** | **−157.3 п.п.** |

**Цена cooldown ОТРИЦАТЕЛЬНА в чистом сумма-пространстве** (не только в
компаунде): отключение cooldown СНИЖАЕТ суммарную посделочную доходность,
хотя добавляет сделок (A: 209→233; B: 370→432). То есть cooldown **НЕ ест**
резерв раннего выхода — новые сделки без cooldown в среднем хуже. Порог
эскалации П2 «cooldown съедает ≥ 50% резерва» требует ПОЛОЖИТЕЛЬНОЙ цены —
**НЕ сработал** (`cooldown_escalate=False` в обеих эпохах). Это опровергает
pre-reg-гипотезу T5 «disarm ≥ as-is» — снята как неверная. Пересмотр правила
cooldown на основании резерва раннего выхода **не требуется**.

### Разбор артефакта «цена cooldown = −0.5 × компонента (б)» (ревью)

Отношение `cooldown_price_sum / component_b_sum` вышло ≈ **−0.50** в ОБЕИХ
эпохах (A: −0.5004; B: −0.5002). Проверено — это **ЭМПИРИЧЕСКОЕ совпадение
полной oracle-политики, НЕ структурная/арифметическая связь**. Доказательства:

1. **Случайное подмножество decision_bars уводит отношение от −0.5** (seed
   фикс.): A при frac=0.5/0.25/0.75 → −0.03 / +0.06 / −0.19; B при frac=0.5
   (seed 0/1) → −0.29 / −0.42. Жёсткого тождества нет.
2. **Разложение разности `sum_nocd − sum_cd` по `entry_bar`:** сделки с
   ОДИНАКОВЫМ баром входа в обоих прогонах дают в разность **РОВНО 0**
   (выход идентичен при одной политике). Вся цена cooldown приходит из сделок,
   УНИКАЛЬНЫХ для одного прогона (A: 43 только в cd на +31.0 и 67 только в
   no-cd на −5.8). Компонента (б) целиком лежит в SL-сделках, идентичных в
   обоих прогонах («общие»). Значит (б) и `cooldown_price` считаются на
   **непересекающихся множествах сделок** — арифметически независимы.

**Вывод:** конвейеры независимы (знаковая проверка настоящая), но число −0.5
**нельзя** подавать как «независимое подтверждение» — это совпадение двух окон.
Знак цены cooldown отрицателен по сырым суммам (A: 324.4 < 361.2;
B: 422.0 < 579.3) и от совпадения не зависит — вывод «cooldown резерв не режет,
эскалация не нужна» остаётся. Пометка добавлена в
`oracle_reserve_numbers.json` (`cooldown_share_note`).

Компаунд-цена (−997 п.п. A, −18392 п.п. B) сохранена в JSON лишь как справка
о знаке; для решения НЕ используется (path-chaotic).

## 6. Честный вывод (вердикт ожидает утверждения порога/знаменателя)

**СТАТУС ЭПОХИ A — post-hoc (дисциплина П8, добавлено по ревью 2026-07-25).**
По ЗАРЕГИСТРИРОВАННОМУ гейту (порог 0.5%/сделку, знаменатель n_dip, пункт П1
pre-reg) эпоха A = ALIVE впритык (0.5037% ≥ 0.5%), как и эпоха B. Понижение A
до «indeterminate» держится на leave-one-out по SL-бакету — этой проверки в
зарегистрированной таблице П1–П4 НЕ было, она введена ПОСЛЕ прогона. Правка
консервативна (понижает claim, не раздувает) и является добросовестной
статистической гигиеной (0.5037 против 0.5 на 9 сделках — шум), но по правилам
это post-hoc и помечается как таковой. Вердикт по эпохе B от этого не зависит
(он проходит и по зарегистрированному гейту, и по leave-one-out).

Заголовок (при знаменателе = все dip эпохи, порог 0.5%/сделку):
**эпоха B — свобода ЖИВА и устойчива; эпоха A — вердикт НЕ определён данными
(coin-flip на одной SL-сделке).** Это ровно «резерв разной природы по эпохам»,
которого ждал план.

- **B 2021-24:** (б) = 1.2833 %/сделку, запас 2.6× над линией смерти,
  выдерживает удаление 20 из 37 SL-сделок → **устойчивый ALIVE**.
- **A 2024-26:** (б) = 0.5037 %/сделку, запас всего +0.54 п.п. при вкладе
  одной сделки ~8.2 п.п.; удаление любой из 9 SL уводит под порог →
  **indeterminate**, НЕ «ALIVE впритык». По A решение нельзя выносить по этой
  эпохе — только по B (или требовать больше данных / другой знаменатель).
- При альтернативном знаменателе = **только SL-обречённые dip** обе эпохи дают
  ~8.2–8.5 %/сделку — на порядок выше порога. Выбор знаменателя меняет запас,
  но не спасает A от хрупкости выборки (9 сделок).
- Компаунд-числа (Reserve_B) отброшены как path-chaotic/anchor-inflated. Цена
  cooldown в чистом сумма-пространстве отрицательна (−0.50 от (б)) → правило
  cooldown резерв не режет; пересмотр НЕ требуется.

### Требует утверждения пользователя ДО того, как число станет вердиктом
1. **Порог гейта (б):** 0.5%/сделку (из плана) — подтвердить.
2. **Знаменатель компоненты (б):** предлагается `n_dip` (все dip эпохи). Тогда
   B = 1.2833% (устойчиво), A = 0.5037% (хрупко). Альтернатива `n_dip_sl` даёт
   ~8.5%. Выбор за пользователем.
3. **Как трактовать эпоху A:** предлагается «indeterminate» (вердикт держится
   на одной SL-сделке из 9). Подтвердить, что решение по жизнеспособности
   ведём по эпохе B, а A не используем как основание ни за, ни против.
4. **Цена cooldown:** знак отрицательный и в компаунде, и в чистом
   сумма-пространстве (правило резерв НЕ режет). Предлагается: пересмотр
   правила cooldown НЕ инициировать. Подтвердить.
