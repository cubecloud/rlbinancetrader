# Кэширование слоя данных (spotrl/data) — отчёт о реализации

Дата: 2026-07-25. Ветка задачи: кэш материализованных окон `WindowData`.
Правились только `spotrl/data/` и `spotrl/tests/`. Коммитов не делал.

## Что сделано

- `spotrl/data/cache.py` — новый модуль, класс `WindowCache` (обёртка над
  `DataSource`). Материализует результат `load_window` в parquet + json-манифест,
  атомарная запись, инвалидация по ключу, отказ кэшировать живой край.
- `spotrl/data/sources.py` — добавлен метод `cache_key_fields()` в `ParquetSource`
  и `PgSource` (идентифицирующие параметры источника для ключа, без окна). Больше
  ничего в источниках не менял.
- `spotrl/tests/test_data_cache.py` — 16 тестов (быстрый набор, без базы).

Стенд запуска: conda env `rlbinancetrader` (Python 3.9.21, pandas 1.5.3,
pyarrow 21). Системный anaconda-python 3.11 не годится — там pyarrow не грузится
(libssl.so.1.1).

## Ключ кэша и инвалидация

Ключ = sha256 от канонизированного (сортировка ключей, epoch-ns для времени)
словаря ВСЕХ компонентов, влияющих на данные:

- `source_kind` (`pg`/`parquet`), `table` (PG) или `path` (снимок);
- `columns` — упорядоченный набор колонок;
- `timeframe`, `origin`, `extended` (флаг расширенного kline);
- `last_full_bar` — параметр вызова `load_window`, добавляется кэшем отдельно
  (меняет набор баров, поэтому обязан быть в ключе);
- границы окна `window_start_ns`, `window_end_ns` — нормализованы через
  `_as_naive_utc` и канонизированы в epoch-ns ДО хэша (строка `"2024-03-10 05:00"`
  и `Timestamp` дают один ключ);
- `dbbinance_version()` (версия пакета базы);
- `FEATURE_BUILDER_VERSION` (версия билдера признаков, `state_v0`);
- `CACHE_FORMAT_VERSION` (`wc1`) — версия формата самого кэша.
- Для снимка дополнительно `st_size`+`st_mtime_ns` файла parquet.

Инвалидация — жёсткая: любой изменившийся компонент даёт другой sha256 → другой
файл → промах → данные читаются заново. Плюс на чтении сверяется `parquet_sha256`
из манифеста; несовпадение (битый/недописанный файл) трактуется как промах.
Тихих попаданий на устаревших данных нет.

Две задокументированные границы прокси-версий:

- Снимок (`ParquetSource`): ручная строка `FEATURE_BUILDER_VERSION` могла бы дать
  тихий устаревший хит при пересборке снимка по тому же `path`. Закрыто добавлением
  `st_size`+`st_mtime_ns` файла в ключ — пересборка меняет ключ (тест
  `test_invalidation_parquet_rebuild`).
- База (`PgSource`): единственный доступный прокси версии данных —
  `dbbinance_version()`. Ревизия отдельных строк в самой базе без смены версии
  пакета кэшем не отлавливается. Это ограничение снимается правилом живого края
  (ниже): у живого края, где и происходит ревизия, ничего не кэшируется.

## Решение по живому краю

Кэшируем ТОЛЬКО закрытые исторические окна. Правило (на этапе записи, по
ФАКТИЧЕСКОМУ последнему бару, не по запрошенному `end`):

    last_label + step <= now - live_margin * step   (live_margin=2 по умолчанию)

Обоснование по семантике `PgSource.load_latest_closed` (`sources.py:320`):
последний ЗАКРЫТЫЙ бар может быть переписан дозагрузкой базы (ревизия
volume/trades), поэтому «закрыт» ≠ «окончателен». Поэтому окно у края не
кэшируется ЦЕЛИКОМ, а не «без последнего бара»: вариант «без последнего бара»
вернул бы на тёплом чтении на один бар МЕНЬШЕ, чем на холодном, для того же
вызова `load_window(start, now)` — молчаливое изменение поведения и провал
побитового `cold == warm`.

Следствия: снимок 2024 (`ParquetSource`) кэшируется всегда; PgSource-окно у `now`
— нет; онлайн-путь `load_latest_closed` целится в `now` и проксируется сквозь
обёртку БЕЗ кэша. `now` инъектируется (параметр конструктора), дефолт
`utcnow()`; в тестах фиксируется 2026-01-01, чтобы синтетика 2024 кэшировалась.

## Гейт (числа)

Тест `test_gate_cold_equals_warm_no_db_access`:

- `diff_elements = 0` — cold и warm ПОБИТОВО одинаковы. Проверялась ПОЛНАЯ
  идентичность (не `bitwise_gate`, который сравнивает лишь пересечение колонок и
  игнорирует meta/source): `index.equals` + `columns` + `data_hash()` (sha256 от
  C-contiguous матрицы) + `source` + `meta` (meta хранится в манифесте и
  восстанавливается дословно). Плюс assert: `data` float64 C-contiguous, индекс
  `datetime64[ns]` — pyarrow round-trip это держит.
- `warm_get_fetcher = 0` — тёплое чтение НЕ вызывает `PgSource._get_fetcher`
  (счётчик-spy на самом методе; на холодном 1, на тёплом 0).
- `warm_fetch_calls = 0` — счётчик `pg_resample_to_timeframe` не растёт (в базу
  не ходим). `inner.load_window` на тёплом не зовётся вовсе.

Ускорение (`test_warm_read_speedup`): фейковый fetcher соsleep 50 мс, эмулирующим
round-trip в PostgreSQL. Число отражает СТОИМОСТЬ ИЗБЕГАЕМОГО запроса, а не
parquet-IO. Замер: t_cold ≈ 53.7 мс, t_warm ≈ 2.5 мс, **speedup ≈ 21.8x**. На
реальной базе выигрыш будет тем больше, чем дороже запрос; отдельное db-число
можно снять маркером `@pytest.mark.db`.

## Тесты и покрытие

16 тестов, все зелёные, быстрый набор целиком ≤1 c: попадание/промах;
инвалидация по КАЖДОМУ компоненту (границы окна, last_full_bar, колонки, версия
dbbinance, версия билдера, версия формата, пересборка снимка); атомарность (сбой
`os.replace` после temp → нет финального файла, читатель видит промах, `*.tmp`
игнорируется); отказ кэшировать живой край; обход кэша для `load_latest_closed`;
побитовый гейт; ускорение; продакшн-ветка `now=None` (utcnow); каноничность ключа
(строка == Timestamp); параллельная запись одного ключа 8 потоками.

Покрытие `spotrl/data/cache.py` = 91% (≥85%). Быстрый набор пакета проходит
(4 skip — slow/db без данных/базы). Отдельно: `tests/test_isolation.py`
(docstring-линт) падает на файлах `spotrl/analysis/*` — это НЕ мои файлы (там
работает другой агент над oracle-резервом, файлы появились в ходе сессии); мои
`data/cache.py` и `tests/test_data_cache.py` линт проходят.

Атомарность/потокобезопасность: запись через `tempfile.mkstemp` (УНИКАЛЬНОЕ имя
temp на писателя) в ТОЙ ЖЕ директории кэша + `os.replace` (в пределах одной ФС —
атомарно). Уникальность имени критична при параллельном холодном старте
(SubprocVecEnv): несколько сред пишут один ключ, детерминированное имя temp дало
бы гонку с заменой недописанного файла. Директория кэша — параметр конструктора,
дефолт `$SPOTRL_CACHE_DIR` либо `~/Data/rlbinancetrader/window_cache`, не хардкод.
