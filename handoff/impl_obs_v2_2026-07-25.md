## 1. Что СДЕЛАНО (durable, с тестами)

### 1.1 ObservationSpec v2 как версионированные данные
`spotrl/spec/observation.py` — добавлен состав v2, фабрика `ObservationSpec.v2()`,
константы нормировки `SPEC_CONSTANTS_V2`, метод `spec_hash()` (sha256 состава +
порядка + констант, НЕ μ/σ), `describe()` пишет константы и хэш в манифест.
v1 остаётся ДЕФОЛТОМ (`EnvConfig.obs_spec`), поэтому среда и все прежние тесты
не тронуты. Тесты: `test_observation_spec_v2_composition`,
`test_observation_spec_v2_constants_in_manifest`.

Версия помечена **`v2-draft`**: СОСТАВ и порядок колонок зафиксированы, но часть
констант нормировки предварительна (см. ниже) — авторитетным `v2` хэш станет
после их фиксации в машине состояния среды.

Размер v2 = **38** (market 18 + agent 14 + world 3 + reserved 3).

Состав v2 (имя — форма нормировки):

БЛОК РЫНОК (17):
- Цены (6): `m_ret_close`,`m_ret_high`,`m_ret_low`,`m_vwap_ret` = Δlog(...);
  `m_hi_close`=(high−close)/close, `m_close_lo`=(close−low)/close. Первый бар=0,
  БЕЗ bfill. (Замечание: оригинал `prepare_ret_obs` делал `pct_change` по
  ЛОГ-цене — это НЕ доходность; в v2 зафиксирована истинная лог-доходность Δlog,
  как уже делает `builder.precompute_market_features` для close.)
- Торговые числа (3), безразмерные: `m_aggr_buy_frac`=taker_buy_base/base_volume
  (vol=0→0.5); `m_avg_trade_size`=log(base_volume/trades)−log(rolling_median),
  trades=0→0; `m_rel_volume`=log(quote_volume/rolling_median_24h), .shift(1),
  clip ±3. `taker_buy_quote` не берётся (дубликат).
- Сигналы v7 (9): `m_entry_signal`,`m_trans_entry_signal` (булевы);
  `m_buy_margin`,`m_sell_margin`,`m_bounce_pct`,`m_leg_age` (непрерывные
  составляющие, есть в state_v0: buy_margin/sell_margin/bounce_pct/leg_age_h);
  `m_exit_flag` (_exit[i]); `m_leg_dn` (leg_dn ТЕКУЩЕГО бара — определяющий
  разделитель гейта выхода, entered_on_up его не заменяет); `m_regime_code`.

БЛОК СОСТОЯНИЕ АГЕНТА (14):
- `a_in_position` (0/1); `a_unreal_pnl` — ЧИСТЫЙ, clip ±0.5; `a_peak_unreal` —
  ЧИСТЫЙ; `a_price_drawdown`=price/peak_price−1 (≤0); `a_dist_to_sl`,`a_dist_to_tp`
  — ВАЛОВЫЕ; `a_entered_on_up` (0/1); one-hot pos_tag фикс. порядка
  `a_pos_tag_none`,`a_pos_tag_dip`,`a_pos_tag_transition`; `a_cb_active`;
  `a_cb_cleared_today`; `a_cooldown_remain`=remaining/1440 (0..1);
  `a_days_in_trade`=tanh(bars/median_hold), median_hold=2442.

БЛОК ПРАВИЛА МИРА (3): `w_data_age`,`w_breaker_armed`,`w_equity_drawdown`

- проверено (можно фиксировать): median_hold=2442, rel_volume_median_window=24h,

**Находка (train/serve-риск).** При leg_dn из НЕкаузального `state_v0_2024`
гейт выхода 2024 проваливался: unseparated 293902 из 293933. Причина —
entered_on_up = not leg_dn[decision_bar] считается по ДРУГОМУ leg_dn, чем тот, на
котором работал v7. Это ровно мастер-инвариант «один прогон» из докстринга
`e12_markov_gates.exit_gate`. Вывод для реализации: leg_dn (и любой признак,
селектирующий смысл действия) обязан браться из ТОГО ЖЕ каузального источника в
train и serve, иначе марковость ложно ломается. Числа выше — на каузальном.

## 2. Что НЕ сделано (осталось, с оценкой и планом)

Приоритет из ТЗ соблюдён: сначала скрытое состояние мира и его гейты
немарковости. Дальше — крупный, ещё не сделанный блок:

### 2.1 БЛОКЕР состояния агента: в среде НЕТ машины скрытого состояния мира
`spot_env.step()` сегодня НЕ ведёт: счётчик cooldown, halt CB по календарному дню,
`entered_on_up` на входе, `pos_tag`, `peak_price`. `breaker_cooldown_bars=1440`
(config.py:41) в step() не читается — есть только мгновенный флаг просадки
(spot_env.py:206). Пока это не построено, поля `a_entered_on_up`,`a_pos_tag_*`,
`a_cb_active`,`a_cb_cleared_today`,`a_cooldown_remain`,`a_price_drawdown`,
`a_days_in_trade` НЕЧЕМ заполнять из книги — это НЕ листовая правка spec, а
машина состояния. Её надо строить ПЕРВОЙ (root cause), spec-вектор — лист.

План (ordered):
1. Расширить `StateDataset` + снимок колонками `entry_signal`,
   `trans_entry_signal`, `exit_sig`. Их НЕТ в state_v0 (там есть непрерывные
   составляющие buy_margin/sell_margin/bounce_pct/leg_age_h и leg_dn, но НЕ
   булевы entry/trans/exit_sig). `entry_signal` берётся из объекта v7 (уже
   умеем: `stats._strategy._entry`). Нужно выгрузить также `_trans_entry` и
   `_exit` в снимок. Без них `pos_tag` (dip vs transition) среда из своей книги
   не восстановит.
2. В `reset()/step()/TradeBook`: cooldown remainder=remaining/1440; cb_active;
   cb_cleared_today по `self.state.index[t].date()`; entered_on_up=not
   leg_dn[t] на баре открытия; pos_tag из сигналов на баре открытия; peak_price
   → price/peak_price−1; tanh(bars/2442). Мутация ТОЛЬКО в step/book, геттеры
   чистые (иначе падает Т2).
3. Расширить `write_observation/build_observation/AgentState/WorldState` под
   14 полей агента; переключить `EnvConfig.obs_spec` на v2.

### 2.2 Рыночный блок и нормировка (builder)
`precompute_market_features` считает только 8 признаков v1. Нужно: 6 цен (Δlog +
внутрибарные, warmup=0), 3 торговых числа (скользящая медиана .shift(1), clip
фикс. порогами), 8 сигналов v7. Скользящие окна — строго `.shift(1)`.

### 2.3 Гейты, ещё НЕ реализованные для v2
- **чистота Э1.2б на v2**: `_obs()` дважды побитово равен — сейчас зелёный на
  v1 (test_t2), для v2 надо повторить после расширения полей.
- **утечка**: признак на префиксе [0:t] == на полном ряде в t. ВАЖНО: сегодня
  МЕРИТЬ НЕЧЕГО — ни одного скользящего признака в v1 нет. Гейт станет
  содержательным только после ввода vwap/rolling-median/rel_volume (2.2).
  Не отмечать его зелёным вхолостую.
- **парность источников** для новых колонок (PgSource vs ParquetSource) —
  инфраструктура `bitwise_gate` готова (data/sources.py), нужен тест на новом
  наборе колонок.
- **паритет env↔expert-log (сильнее 1.2а)**: прогнать среду потоком экспертных
  действий v7 и побарно сверить `agent_state()/world_state()` с разделителями
  expert-лога → 0 расхождений. ЭТО главный защитный чек копирования (гейты 1.2а
  доказывают разделимость решения ЭКСПЕРТА, но не что СРЕДА кладёт те же числа в
  наблюдение). Драйвер экспертных действий в среде пока не написан.
