## 0. Зачем supervised, а не RL (кратко, чтобы был контекст)

Свобода = «выйти из dip-позиции РАНЬШЕ v7, если сделка идёт в стоп». Резерв
(потенциал улучшения над v7) сосредоточен в SL-сделках. За всё окно обучения
2021-01..2024-03 (1 675 739 минутных баров): **272 сделки v7, из них 245 dip,
из них ~37 SL**. Это связывающая величина — для RL мало (высокая дисперсия
advantage на 37 эпизодах, коллапс поглощающего действия, хрупкий критик — всё
это нас останавливало). Проба достижимости (K3) показала: SL заранее ОТЛИЧИМ из
наблюдения (OOS-AUC 0.848, CI_lo 0.735 > порога 0.60, shuffle-контроль чист).
Значит это по сути задача КЛАССИФИКАЦИИ на уровне бара (702 838 dip-баров —
данных много), а не задача RL. Supervised использует бары эффективнее и снимает
хрупкость RL. Ограничение честное: итоговый ВЕРДИКТ всё равно опирается на ~37
SL-сделок → CI эффекта широкий; supervised не создаёт новых сделок.

## 3. ТОЧНЫЙ рецепт метки (таргета) — самое важное

Гранулярность — **dip-in-position БАР** (ровно там, где принимается решение
«держать/выйти»).

- **y = 1**, если сделка, которой принадлежит бар, закрывается по стопу
  (`exit_reason == "sl"`); иначе **y = 0** (восстановление / штатный / тейк).
- Метка «размазана» на ВСЕ бары сделки от `entry_bar+1` до `exit_bar`.
- **Законность подглядывания:** метка знает будущее (исход сделки известен после
  закрытия) — это НОРМА для supervised-цели. Запрет на подглядывание —
  только в ПРИЗНАКАХ: obs бара строго причинный (rolling `.shift(1)`, без bfill),
  что уже под гейтом утечки. Правило: цель может смотреть в будущее, признаки —
  нет.
- Мин-холд: первые ~60 баров сделки (`a_days_in_trade < 0.0245`) выходом НЕ
  трогаем (как в RL-драйвере) — не дёргаемся сразу после входа.

### Числовой пример (для наглядности)
- Сделка №58: вход бар 10000 цена 40000, закрыта по стопу на баре 10600 по 38800
  (−3%). Бары 10001..10599 → y=1.
- Сделка №59: вход 11000 по 41000, просадка до 40200, восстановление, выход по
  сигналу бар 11900 по 42000 (+2.4%). Бары 11001..11899 → y=0.
- На бою на новой сделке: как только p_SL ≥ τ (напр. 0.6) — выходим. Верное
  срабатывание на SL: выход ~39500 вместо 38800 → +1.8% к v7. Ложное на
  восстановлении: выход ~40200 вместо 42000 → −4.4% упущенного роста. Размен
  контролирует τ и гейт.

### Вариант метки (обсудить, НЕ дефолт)
Можно было бы регрессировать per-trade дельту «выход сейчас − выход v7» — но это
вернёт проблему дисперсии магнитуды (она убила MSE-критик в RL: OOS-AUC 0.42).
Поэтому ДЕФОЛТ — БИНАРНАЯ метка «SL?», а размен ловим порогом τ по гейту. Так
надёжнее.

## 4. Признаки и модель

- Признаки: `obs_cols` минус `_CONST_ON_DIP`. K3 нашёл несущими сигнал (permutation
  importance): **`a_peak_unreal` (0.149), `w_equity_drawdown` (0.109),
  `a_entered_on_up` (0.080), `a_unreal_pnl` (0.024)** — НЕ тривиальный
  `a_dist_to_sl` (близость к стопу почти не важна → сигнал не «цена уже у стопа»,
  а профиль сделки + режим, доступный раньше).
- Модель: дешёвая (K3 брал `HistGradientBoostingClassifier` и `LogisticRegression`,
  `StandardScaler`). GBM дал более высокий OOS-AUC. Логрег даёт калиброванную
  вероятность — удобно для порога. На ваше усмотрение; главное — честная OOS-оценка.

## 5. Защита от утечки (ОБЯЗАТЕЛЬНО — иначе результат мусор)

1. **Деление train/val ПО СДЕЛКАМ, не по барам.** Соседние бары одной сделки
   почти идентичны — если они попадут и в train, и в val, модель «увидит ответ».
   K3 делил по сделкам (сплит 70/30 по сделкам, эмбарго естественное).
2. **Временной порядок:** учить на ранних сделках, проверять на поздних (или
   временная кросс-валидация с эмбарго). Не учить на будущем для предсказания
   прошлого.
3. **Shuffle-контроль:** перемешать метки → OOS-AUC обязан упасть к 0.5
   (K3: усреднять по ≥25 перестановкам, при 12 SL-сделках в тесте одиночный
   прогон шумит — дал 0.65 из-за дисперсии, усреднение сняло до 0.48).
4. **Финальный holdout 2026-01..07 НЕ трогать** (вскрывается один раз по
   отдельному pre-reg). tune-фолд 2024-03..2026-01 — только OOS-замер, резать
   явно до 2026-01.

## 6. Механика решения и калибровка порога τ

- На каждом dip-in-position баре: p_SL(t) = модель(obs_t). Первый бар с p_SL ≥ τ
  (и после мин-холда) → ранний выход. Иначе — штатный выход v7.
- **enforce_v7_exit ОСТАЁТСЯ:** мы можем выйти только РАНЬШЕ, никогда не
  пропускаем выход v7. Худший случай ограничен (леса на месте). Паритет:
  под «никогда не выходить раньше» набор сделок обязан совпасть с v7 (272/272)
  и recall штатных выходов = 1.0.
- **Порог τ подбирать по ГЕЙТУ, не по AUC/точности.** Критерий — деньги:
  максимизировать сумму per-trade дельт (portfolio-критерий, см. §7) на
  валидационном срезе. Высокий τ — реже выходим (меньше ложных, меньше резерва),
  низкий — чаще (больше резерва, больше вреда восстанавливающимся).
- Опция против дёрганья: требовать p_SL ≥ τ на k подряд барах (персистентность).

## 7. ПРОВЕРКА (гейт + контроли) — готовый инструмент

Переиспользовать `spotrl/analysis/eval_gate_v2.py` (уже откалиброван):
- Критерий «эффект есть» = (A) И (B):
  - **(A) портфель:** `Σ Δ_i > 0` И нижняя граница 95% bootstrap-CI суммы `> 0`
    (ресэмпл по СДЕЛКАМ; нули нейтральны — разреженность не размывает).
  - **(B) качество действий:** на acted-subset односторонний Wilcoxon `p<0.01`
    И нижняя граница bootstrap-CI медианы acted-дельт `> 0`.
  - `Δ_i` = `(ret(exit_i, entry) − ret(v7_exit, entry))·100` п.п., ЕДИНАЯ
    двусторонняя комиссия для всех политик.
- **КАЛИБРОВКА ПРИБОРА (обязательна перед вердиктом):** прогнать через гейт
  ORACLE и RANDOM.
  - ORACLE (выход в оптимальный по будущей цене момент) обязан ПРОЙТИ. На train
    2021 эталон: `Σ +648.71 пп, CI [+555.97, +746.66], acted 209/245`.
  - RANDOM (выход в случайный момент, тот же счётчик) обязан ПРОВАЛИТЬСЯ:
    `Σ −55.73 пп, CI [−170.88, +59.01]; доля Σ>0 = 0.00 на 200 реализациях`.
  - Только если oracle проходит И random валится → `instrument_valid=True`.
- **Разбивка K2** (`k2_tagged`, стр. 229): дельта РАЗДЕЛЬНО по SL-сделкам и
  восстанавливающимся + по знаку oracle-резерва. Обязательно показать: сколько
  из 37 SL-сделок затронуто и какова там дельта (там резерв ~1.28%/сделку по
  Э0.2). Для сравнения — прошлый RL-прорыв (K4cls, 300k): SL 5/37, Σ +34.9 пп,
  acted_mean +6.98 пп; общий минус был из-за переусердствования на восстановлении.

## 8. Честные ограничения (сообщить в вердикте)

1. Вердикт статистически ограничен ~37 SL-сделками (train) — CI эффекта широкий.
   Supervised эффективнее по барам, но сделок не добавляет.
2. Ранняя зона слабее (K3: AUC 0.85 у развязки, 0.70 CI_lo 0.539 в начале
   удержания) — выход будет срабатывать ближе к стопу, беря не весь пик резерва.
   Мерить, ГДЕ внутри удержания срабатывает.
3. Смена режима 2021-2024 → 2024-2026: проверять на tune-фолде OOS до holdout.
4. Не тюнинговать порог/модель бесконечно: если на OOS Σ CI включает 0 или не
   бьёт random — честный вывод «эффекта нет», не подгонять.
