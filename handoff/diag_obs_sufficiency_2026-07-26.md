# Диагностика достаточности obs v2 для головы 0 — ВЕРДИКТ (b)

Тест: `scratchpad/diag_obs.py`. Регуляризованные LR (C=0.5, L2, balanced) и дерево
(max_depth=4) на СЕМАНТИЧЕСКИХ входах правила v7 (без сырых ценовых/объёмных осей,
без самих решений v7). Метрика — AUC/AP (средняя разделимость), не L∞-зазор.

## Вердикт: (b) obs v2 ДОСТАТОЧНО для головы 0
- Семантика разделяет классы IN-epoch И OUT-of-epoch (LR AUC 0.92-0.99 обе задачи,
  обе стороны). Handoff-число 0.5/-2.6 — это L∞-зазор ±80-объектива (один худший
  бар), НЕ мера разделимости; оно не исключает высокую среднюю разделимость.
- v7 — простое пороговое/булево правило; неглубокое дерево/L2-LR его выражают. Раз
  маломощная регуляризованная модель обобщает через эпоху — вход правила в obs.
- Названный ранее «недостающий вход выхода v7» (b2b/legflip-латч) НЕ отсутствует:
  вся коллизионная популяция 100% объяснена наблюдаемыми pos_tag+regime.
- Провал клона (кросс-эпоховый зазор -109/-157 nat) — это ±80 logsumexp +
  hard-negative-mining, максимизирующий L∞-маржу по шумовым осям (мемоизация), а не
  MDP-недостаточность.

## Оговорки (честно)
- Малая выборка: 96-272 позитива на эпоху → доверительный интервал out-of-epoch
  recall широкий.
- AUC ~0.93 на выходе — не идеальная сепарация; точный бар-в-бар гейт
  (recall>=99.5% И FPR<=3e-7 через скалярный сдвиг, ~20 nat) маломощной моделью
  out-of-epoch НЕ достигается (recall_out 0.95, fpr ~0.2). Но argmax-ёмкость уже
  доказана in-sample (162/162, 150/150). Точность гейта — вопрос объектива/
  калибровки, не состава obs.

## Фикс (следствие b)
1. Spec НЕ трогать (obs v2 достаточен для головы 0).
2. Переучить клон регуляризованно: обычный взвешенный CE/калиброванный, реальный
   weight_decay + клип |d|, БЕЗ logsumexp-max-margin по всему пулу. Гейт-объектив
   ±80 выкинуть — он и есть причина мемоизации и отравленной инициализации PPO.
3. Кросс-эпоховый AUC/recall ввести в гейт как go/no-go (уже реализуемо).
4. Не засевать PPO текущей ±80-политикой.
