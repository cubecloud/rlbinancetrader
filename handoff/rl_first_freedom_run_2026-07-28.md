нужна ОБЁРТКА-драйвер, которой в каркасе НЕТ:

- в PPO-буфер кладётся СЭМПЛ агента (loss-маска головы 0 = dip-only уже гарантирует,

Драйвер — новый компонент; ДО калибровки его надо ПАРИТЕТНО проверить: под argmax

только p(FLIP) поднимается, dip-сделки закрываются РАНО → dip-холд-бары исчезают →
метрика на горстке баров рушится (n_dip→0). Т.е. **коридор [1%,5%] на per-bar
средней — плохо определён для поглощающего выхода**: устойчивого 3% не существует.

### П3. Калибровка на ОДНОМ стартовом rollout (2021, N_STEPS=8192, драйвер honor_dip=True)

- **dip-баров в rollout: 825 / 8192** (sanity > 0). ✓
- **p(FLIP)@dip клона на старте = 0.017%** (клон почти детерминирован; на первом
  rollout ent_coef на сэмплинг НЕ влияет — это loss-член, сэмплинг задаёт клон).
- **Масштаб dip-advantage (§6 п.9):** dip-std = 6.90e-3, full-std = 2.32e-3,
  **ratio = 2.968**. Нормировка по ПОЛНОМУ минибатчу даёт dip-advantage
  **rms = 3.08** (раздут ≈3× и смещён статистикой forced-баров) против
  **rms = 1.000** при нормировке по dip-подмножеству. → Каркас ИСПРАВЛЕН:
  `ppo_scaffold.py` нормирует advantage статистикой dip-подмножества (было —
  полный минибатч). Это обязательная починка, а не опция.
- **β (правило):** на старте политика == клон → KL=0, ‖∇KL‖≈5e-7 → правило «на
  первом rollout» ВЫРОЖДЕНО (даёт β≈635). Замер при РЕАЛИСТИЧНОМ смещении (один
  PG-шаг, lr семени): ‖∇PG(dip)‖=3.39e-3, KL@1шаг=1.15e-5, ‖∇KL@disp‖=9.18e-4 →
  **β = 0.1·‖∇PG‖/‖∇KL@disp‖ = 0.369**. Чуть выше a-priori ориентира 0.05–0.2
  (~1.8×), но свип при β=0.369 держит KL≈5e-3 (<< cap 0.05) и p(FLIP)@dip в
  коридоре → значение самосогласовано. Консервативная альтернатива β=0.2 тоже
  допустима (больше запаса разведки, KL ещё меньше cap).
- **ent_coef (правило p(FLIP)@dip ∈ 1–5%):** entropy-свип (K=60 апдейтов на
  буфере, β=0.369, dip-only норм):

  | ent_coef | 0.0 | 0.005 | 0.01 | 0.02 | 0.05 | 0.1 | 0.2 |
  |---|---|---|---|---|---|---|---|
  | p(FLIP)@dip | 3.77% | 3.60% | **3.52%** | 3.64% | 3.82% | 4.11% | 12.47% |
  | KL | 4.5e-3 | 4.8e-3 | 4.9e-3 | 5.0e-3 | 5.0e-3 | 5.2e-3 | 1.5e-2 |

  Разведка в коридор [1%,5%] обеспечивается САМОЙ PG-динамикой на 825 dip-барах

## 3. ВТОРАЯ НАХОДКА (pre-reg §6 п.9 не реализован) — блокирует осмысленность прогона

`ppo_scaffold.py:118-120`: advantage нормируется по ПОЛНОМУ минибатчу
(`(A-A.mean())/A.std()`), тогда как в policy-градиент идут <1% dip-баров (маска).
Статистики нормировки задаются forced-барами (99%+), а dip-advantage делится на
их `std`. При bias-init критике (V≡mean(G)) advantage dip-бара = return-to-go −
mean(G), делённый на std forced-баров (длинные холды → большой разброс) →
PG-сигнал головы 0 сжимается относительно KL-якоря и энтропии. Не инверсия знака,
но заметное ослабление единственного обучаемого сигнала. Pre-reg §6 п.9 требует
проверить на первом rollout и при необходимости нормировать по dip-подмножеству —
в коде такого пути НЕТ. Нужно добавить опцию нормировки advantage по dip-маске и
замерить оба варианта на первом rollout ДО бюджетного прогона.

## 4. ЧТО ПОДТВЕРЖДЕНО КОРРЕКТНЫМ (чтобы команда доверяла)

- **Агент-стейт считается средой на лету** (`observe()` →
  `build_observation(market, self.agent_state(), self.world_state(), spec)`), НЕ
  читается из предвычисленных колонок. Утечки «агент-стейт под чужой политикой»

  кодом `spot_env.py:467-475`).
- **Клон/семя бит-в-бит** в каркасе (логиты Δ=0), критик bias-init = const mean(G),
  gamma=1.0 форсится (`build_scaffold` отвергает gamma≠1.0). ✓
- **log_prob/entropy суммируются по головам** (sb3 MultiCategorical), но головы
  SL/TP вырождены (nvec=1) → их вклад ровно 0; ratio и энтропия эффективно только
  по голове 0. Корректно. ✓
- **KL-якорь** — `KL(clone‖current)` головы 0 по всем барам, клон заморожен
  (requires_grad=False). ✓
- **Клип скейлера** не корёжит бинарные a_in_position/a_pos_tag_dip: std(raw=1)≈
  +1.0, std(raw=0)≈−1.0 при CLIP_STD=10 → деста маски dip точна. ✓
