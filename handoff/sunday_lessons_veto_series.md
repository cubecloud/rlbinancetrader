# Уроки вето-серии (2026-07-21) — ОБЯЗАТЕЛЬНО к учёту в RL-дизайне

Серия: модель-судья (XGBoost) поверх сделок стратегии v6 — «пускать вход или
нет». Полный перебор осей, всё walk-forward с контролями. Итог: вето-задача
НЕ решается, и почему именно — важнее самого итога.

## Матрица результатов (сумма return оставленных сделок на 110 тестовых; база
«пускать всех» = 188.9%)
- Фичи 12 (тракт стратегии): 158.9%
- Фичи 52 (+рыночные производные): 167.3%
- Фичи 75 (+различение сделок): 178.4% ← ПИК
- Фичи 105 (+ещё масштабы): 173.2% (переобучение: рост фич пошёл во вред)
- PCA k=10/20/40/60: 128 / 152 / 174 / 187.6% (монотонно К базе СНИЗУ)
- PCA полный ранг k=85: 186.6% ± 3 по сидам (1 сид из 5 выше базы — шум)
- Выборка 138 → 416 сделок (добавлены 2021-2024): 172.3% (эпохи разные, смесь
  ухудшила)
- Пермутационный контроль во ВСЕХ прогонах чист (на случайных метках судья
  пускает всех).

## Уроки (каждый бьёт прямо в RL-дизайн)
1. ГЕОМЕТРИЧЕСКАЯ метка ≠ ЭКОНОМИЧЕСКАЯ. «Сигнал попал в минимум» и «сделка
   заработала» — разные задачи: bear-блок v6 режет НАСТОЯЩИЕ минимумы (45%!)
   и всё равно удваивает деньги (там +0.2%/сделку, 21% стопов). Награду RL
   строить ТОЛЬКО из P&L симулятора, не из разметки разворотов.
2. Прибыль живёт в ЖИРНЫХ ХВОСТАХ: несколько крупных сделок делают кассу.
   Любая политика, режущая сделки, рискует срезать хвост — судья на этом и
   умер. Для RL: осторожно с action «пропустить вход»; лучший резерв не там.
3. Входы v6 ВЫЖАТЫ: систематически вырезаемого мусора в них нет (доказано
   перебором). Резерв по oracle-экспериментам — в ТАЙМИНГЕ ВЫХОДОВ.
4. Один исторический путь рынка: агент с большой ёмкостью переобучится под
   единственную траекторию изощрённее XGBoost. Обязательны: walk-forward по
   времени (2021-2024 train / 2024+ валидация), пермутация наград, проверка
   сид-устойчивости (у нас разброс сида ±3 п.п. был больше «эффекта»),
   сравнение с якорем «делай как v6».
5. Эпохи рынка РАЗНЫЕ (2021-2024 vs 2024+): смешивание без учёта эпохи
   ухудшало модель. 6. AP/accuracy ≠ деньги (многократный урок проекта) —
   единственный гейт = компаунд/DD в симуляторе против базы v6.

## Рекомендованная архитектура (моё мнение, обсуждалось с юзером 2026-07-22)
Behavioral cloning копии v6 (по state из parquet) как ЯКОРЬ + KL-штраф за
отклонение; RL-свободу дать узко — тайминг выхода; награда из зеркала;
валидация нашим каркасом. НЕ end-to-end агент с нуля.
